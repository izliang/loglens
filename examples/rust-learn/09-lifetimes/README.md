## 关键概念

### 1. 生命周期是"引用的有效期"，不是"变量的作用域"

```rust
let r;
{
    let x = 5;
    r = &x;
}              // x 在这里被释放
println!("{}", r);  // ❌ 编译错误：`x` does not live long enough
```

编译器要保证：**引用的有效期 ⊆ 被引用值的有效期**。这是编译期检查，零运行时成本。

### 2. 函数里的生命周期标注

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str
```

读法：**存在某个生命周期 'a，x、y、返回值都至少活这么久**。实际取的是两个参数中较短的那个。

关键点：

- `'a` 不是"让变量活更久"，而是"告诉编译器它们之间的约束关系"。
- 标注不改变任何运行时行为，只影响借用检查。
- 如果返回的引用只可能来自某一个参数，就只标那一个。

### 3. 省略规则（elision）

编译器按顺序套用三条规则，能推出来就不用手写：

| 规则 | 内容 |
|---|---|
| 1 | 每个引用参数各获得一个独立生命周期 |
| 2 | 只有一个输入生命周期时，它赋给所有输出 |
| 3 | 有 `&self` / `&mut self` 时，`self` 的生命周期赋给所有输出 |

所以这些写法是等价的：

```rust
fn f(s: &str) -> &str              // 规则 1+2
fn f<'a>(s: &'a str) -> &'a str    // 展开

impl Excerpt<'_> {
    fn part(&self) -> &str          // 规则 3：返回值和 self 绑定
}
```

### 4. 结构体持有引用

```rust
struct Excerpt<'a> { part: &'a str }
```

含义：`Excerpt` 实例不能比它引用的数据活得久。谁创建它，谁就要保证数据先存在。

### 5. 'static

两种含义，别混：

- `&'static str`：引用指向的数据活到程序结束（字符串字面量、`Box::leak`）。
- `T: 'static`：**类型 T 里不含短生命周期的引用**，不是"值一定活到永远"。`String`、`i32` 都满足 `T: 'static`。

### 6. 什么时候真的需要手写

| 场景 | 要不要写 |
|---|---|
| 单个引用参数、返回值是引用 | 不用（规则 2） |
| 方法返回 `&self` 的字段 | 不用（规则 3） |
| 多个引用参数、返回引用 | **要写** |
| 结构体/enum 存引用 | **要写** |
| 返回 `&'static str` | 要写 |
| 闭包、迭代器 | 基本不用，交给编译器 |

经验：**先不写，编译器让你加再加**。

## 常见坑

- 以为 `'a` 能延长变量寿命 → 它只是约束，不能改变所有权。
- 多个引用参数时忘了标 → `missing lifetime specifier`。
- 结构体存了 `&str` 却想返回它 → 结构体活得不够久，考虑改成 `String` 拿走所有权。
- `fn get(&self) -> &str` 返回的是局部 `String` → 必须返回 `String` 或 `&'static str`。
- 把 `T: 'static` 理解成"必须活到程序结束" → 它只是"不含短引用"。
